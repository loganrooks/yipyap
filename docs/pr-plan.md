# Phase 1 PR Plan

> **⚠ Partially superseded by Phase 0 findings (2026-05-17).** PR 4
> (Analyzer) and PR 5 (Synthesizer) scopes below are stale relative
> to `docs/architecture.md` "Decisions deferred" (now closed) and
> "Contract changes implied by Phase 0 findings":
>
> - PR 4 still describes onset+pitch analyzer modules
>   (`onsets.py`, `pitch.py`) emitting `list[VoiceEvent]`. The
>   Phase 0 analyzer-driver decision is **ASR-driven**; the actual
>   Phase 1 analyzer is ASR + diarization → `list[WordEvent]`.
> - PR 5 still passes `VoiceEvent` to a single-bank synthesizer. The
>   actual Phase 1 synthesizer is multi-bank-aware and keyed off
>   `WordEvent.speaker_id` (with `None` = single-voice for MVP).
>
> Updated PR 4/PR 5 scopes will land in a dedicated PR-plan revision
> before Phase 1 starts. The other six PRs (scaffold, separator,
> mixer, integration glue, CLI polish, tests) are not affected by
> the Phase 0 contract changes and stand as written.
>
> If you're a contributor about to pick up PR 4 or PR 5: don't
> implement the scope below. Wait for the revision, or pair-think
> through the `WordEvent` / multi-bank shape against
> `docs/architecture.md`.

Eight PRs, each independently mergeable, each leaves `main` runnable. Branch from `main`,
PR back into `main`. Sequence matters only where noted.

For each PR: scope is fixed up front. If scope creeps mid-PR, split it.

## PR 1 — Scaffold

**Branch:** `phase-1/pr-01-scaffold`

**Scope:**
- `pyproject.toml` with project metadata, deps pinned (Python 3.11+).
- `src/yipyap/__init__.py` exposing `__version__`.
- `src/yipyap/cli.py` with argparse — accepts `INPUT OUTPUT`, prints them, exits 0.
- `src/yipyap/errors.py` with `YipyapError`.
- Entry point registered as `yipyap` console script.
- `tests/test_cli_smoke.py` — runs CLI with `--help`, checks exit code.
- `Makefile` (or `justfile`) with `make install`, `make test`, `make lint`.
- `.github/workflows/ci.yml` running lint + tests on push.

**Acceptance:**
- `pip install -e .` works.
- `yipyap --help` prints usage.
- `make test` passes.
- CI is green.

**Do not:** add audio deps, add real pipeline code, add a Dockerfile.

## PR 2 — IO helpers and fixture

## PR 3 — Separator module

**Branch:** `phase-1/pr-03-separator`

**Scope:**
- `src/yipyap/separator/__init__.py` with `separate(in_path, work_dir) -> SeparationResult`.
- `src/yipyap/separator/demucs_backend.py` calling the chosen Demucs variant (from Phase 0
  findings).
- Add `demucs` to deps. Model weights pulled at runtime, cached in user dir.
- `tests/test_separator.py` — runs separator on the fixture, asserts both stems exist,
  asserts combined RMS ≈ original RMS within tolerance.

**Acceptance:**
- Running separator on fixture produces `voice.wav` and `background.wav`.
- Test passes locally (CI may need a smaller mock model — see notes).

**Notes for CI:** Demucs is heavy. Two options: (a) mock the backend in CI and run the
real model only locally (recommended), (b) cache the model in CI. PR 3 picks one and
documents it.

**Depends on:** PR 2.

## PR 4 — Analyzer module

**Branch:** `phase-1/pr-04-analyzer`

**Scope:**

**Acceptance:**

- Tests pass.

**Depends on:** PR 2 (not PR 3 — analyzer takes a path, can use fixture directly).

## Conventions

- Branch off `main`, PR back to `main`.
- One PR title format: `phase-1/PR-NN: short topic` (e.g. `phase-1/PR-03: separator module`).
- Every PR description must include: scope, acceptance criteria, what was tested,
  what was *not* tested.
- Every PR must keep `make test` green.
- Reviewer (human or agent) confirms acceptance criteria literally before merge.

## For automated agents

If a `/goal`-style agent picks up this plan, the PR list above is the unit of work. Each
PR is independently mergeable. The dependencies are listed. Acceptance criteria are
listed and should be verified literally. If acceptance is unclear, the agent should stop
and ask rather than guess.
