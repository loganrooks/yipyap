# Phase 0 — Spike Plan

Two spikes, both throwaway, both required before any Phase 1 PR lands. Outputs are
listening verdicts and a short findings doc, not production code.

---

## Spike A — Source separation on sports audio

**Question:** Can off-the-shelf separation models cleanly split a real sports clip into
"voice" and "everything else"? Specifically, can we get a no-voice stem clean enough
that we can swap the voice without ghost speech bleeding through, and a voice stem
clean enough to analyze?

**Method:**
1. Pick 2–3 real source clips (~20–40s each) covering distinct stressors. Aim
   for variety, not duplicates of the same situation:
   - one with clean talk over light crowd (baseline),
   - one with music swells over commentary (mid-broadcast bumper, replay music),
   - one with crowd peaks during a play (PA voice, whistles, roar).
   Stored locally only — not committed. The model verdict aggregates across clips,
   not from any single sample.
2. Run separation across **at least three architecturally distinct methods**
   so the verdict reflects cross-family signal, not Demucs hyperparameter
   variance. Different training recipes inside one architecture (e.g.
   `htdemucs_ft` vs. `mdx_extra`) are not "different methods":
   - **(1) Demucs family** — hybrid transformer / MDX (`htdemucs_ft` *and*
     `mdx_extra` count together as one method for the cross-family verdict;
     run both as a sanity check on within-family agreement).
   - **(2) Open-Unmix** — Bi-LSTM masking on spectrograms (`umxl` or `umxhq`).
     Architecturally unrelated to Demucs.
   - **(3) MDX-Net via `audio-separator`** — convolutional masking; pick one
     strong UVR MDX-Net model (e.g. an `UVR-MDX-NET-Inst_*` variant).

   **DeepFilterNet** is OPTIONAL — speech enhancement, not separation. It
   produces an enhanced voice and an implicit-by-subtraction background, which
   is a different operational mode. Only reach for it as a fallback if Spike A
   verdicts across the three required methods are inconclusive. See the
   "Trying DeepFilterNet" section in `spikes/README.md`.

3. For each (clip × method) pair, listen to both stems. Note:
   - Bleed of crowd/music into the voice stem (how much, how distracting).
   - Bleed of commentary into the no-voice stem (how much speech you can still hear).
   - Artifacts (warbling, swirling, dropouts).
4. Note runtime per minute of input on CPU (per method — should be stable
   across clips). Record runtime once per method.

**Decision:**
- If at least one method gives both stems "good enough" (subjective — but the no-voice
  stem must not have intelligible speech under it), pick that method and proceed.
- If three families disagree, the disagreement itself is signal — note which method
  dissents and why. If all three agree (good or bad), the verdict is robust.
- If none are acceptable, the project may need a different strategy (e.g., gate the
  whole voice region rather than replace it, or try DeepFilterNet as a fallback).
  Stop and reconvene.

**Deliverable:** A paragraph in `spikes/findings.md` (local-only) recording: clips used,
methods tried, per (clip × method) verdict per stem, runtime per method, chosen method
(verdict aggregated across clips), and a short cross-family commentary on whether
disagreements suggest single-method bias.

## Spike B — Onset-aligned animalese

**Question:** When we drive an animalese sample bank from onset detection + pitch
tracking on the isolated voice stem, does the result sound like animalese over the
original cadence, or does it sound like noise?

Spike B is split into three sub-tests so that two separable failure modes —
**cadence** (rhythm/timing, a function of VAD + onset detection + pitch
estimation) and **timbre** (does the bank itself sound like animalese?) — can
be judged independently:

- **Cadence test** — use the inline sine bank generated by the script. Sounds
  ugly by design; listen *only* for whether the firing rhythm tracks the
  commentator.
- **Timbre test** — use a real animalese sample bank under `spikes/samples/`
  (user-supplied; gitignored). Cadence is held constant; judge the samples.
- **Combined verdict** — real bank mixed with the Spike A background stem.
  This is the closest to the eventual listening experience.

**Method:**
1. Use the voice stem from Spike A.
2. Run VAD (silero-vad) → voiced regions.
3. Inside voiced regions, run onset detection (librosa.onset.onset_detect).
4. At each onset, estimate pitch (librosa.pyin or CREPE).
5. Build / load an animalese sample bank — 5–10 short pitched syllable samples:
   - Cadence test: the inline 3-harmonic sine bank built by the script.
   - Timbre / combined tests: supply a directory of `.wav` samples via
     `--samples-dir <PATH>` (e.g. an animalese.js export or self-recorded clips).
6. At each onset time, pick a random sample, pitch-shift it to the detected pitch
   (optionally biased by `--pitch-offset <SEMITONES>` — see "Known knobs" below),
   place it. Length capped to time-until-next-onset.
7. Render three deliverable wavs:
   - `spike-b-cadence.wav` — inline sine bank, animalese-only.
   - `spike-b-real.wav` — real bank, animalese-only.
   - `spike-b-real-mixed.wav` — real bank + Spike A background stem.

**Decision:**
- If you can hear the cadence of the commentary and the result feels like animalese:
  proceed with the onset path in Phase 1.
- If onsets are too dense, too sparse, or rhythm doesn't track: try one fix
  (filter onsets by energy threshold). If still bad: switch to transcription-based
  fallback for Phase 1.
- If samples sound bad even with good timing: revisit the sample bank design before
  Phase 1 (different base samples, different pitch-shift method).

**Deliverable:** Three output wavs and a paragraph in `spikes/findings.md`:
- `spike-b-cadence.wav` — cadence-only verdict (inline bank).
- `spike-b-real.wav` — timbre verdict (real bank).
- `spike-b-real-mixed.wav` — combined verdict (real bank + Spike A background).
- Verdict per sub-test and recommended path for Phase 1.

## Listening protocol

These spikes only matter if a human listens carefully. Tighten the listen:

- **Spike A:** A/B the same 10s segment from both models back-to-back with
  eyes closed (avoid model-name bias). Repeat per clip. Aggregate the verdict
  across clips — don't decide from a single sample.
- **Spike B:** listen once at **0.75× speed** first — slowing playback exposes
  alignment slips that mask at full speed. Then listen again at full speed for
  the artistic judgement.

## Known knobs / non-failures

Two things will look like failures but aren't:

- **VAD coarseness.** silero-vad on continuous commentary typically returns one
  big voiced region, not phrase- or breath-level segments. This is expected at
  Phase 0. Finer phrase/breath gating is Phase 2 work, not a Spike B failure.
- **High-tessitura animalese.** Real animalese sample banks are pitched up. If
  the default pitch mapping pulls samples into muddy bass, try
  `--pitch-offset 12` (one octave up). This is a knob to explore, not a
  refutation of the onset-driven approach.

## Checklist

- [ ] Source clip(s) selected and placed in `spikes/inputs/`.
- [ ] Spike A run with two separation models. Verdict written.
- [ ] Spike B run on Spike A's chosen voice stem. Verdict written.
- [ ] Decisions recorded back into `docs/architecture.md` ("Decisions deferred"
      section).
- [ ] `spikes/findings.md` summarized into a short note in `docs/listening-log.md` once
      that file exists in Phase 1.

## What NOT to do during spikes

- Don't build modules. Don't create a CLI. Don't write tests.
- Don't commit audio. Don't commit findings.
- Don't tidy the spike code "for re-use." It's throwaway.
- Don't proceed to Phase 1 PRs until both verdicts are written.
